# AI-Based Personalized Multi-Subject Learning and Student Weakness Detection System

This is a BTech-major-project research prototype. Its central contribution is a reproducible adaptive-learning pipeline: a latent-skill simulator creates realistic multi-subject histories, temporal features feed multiple ML mastery classifiers, and a novelty-aware policy recommends the next question and difficulty.

> **Research integrity:** all records generated by this repository are explicitly **synthetic / simulated**. They must never be described as real student-study data, nor should model metrics generated here be generalised to real learners without an approved real-data study.

## Architecture

```text
Question bank (150 MCQs / 5 subjects) ──┐
Latent-profile student generator ───────┼──> learning-attempt simulator ──> CSV + SQLite
                                        │                    │
                                        │                    └──> chronological feature engineering
                                        │                                  │
Streamlit student/research interface <──┴── ML suite (LR / RF / XGBoost) <─ student-level split
                                                            │
                                             mastery prediction → weakness reasons → adaptive recommendations
```

The UI is intentionally thin. The simulator, feature pipeline, models and experiments can all run directly from Python.

## Included capabilities

- 150 modular MCQs: one Easy, Medium, and Hard item for each of 50 concepts across DSA, DBMS, Operating Systems, Computer Networks, and Software Engineering.
- SQLite schema for students, subjects, topics, questions, attempts, simulation runs, predictions and recommendations.
- Reproducible synthetic learner profiles with correlated general, subject and topic abilities; simulation controls include cohort ability mix and difficulty mix.
- Item-difficulty, response-time, noise, repeated practice and learning-progression simulation. Scale selections include 10 through 10,000 synthetic learners.
- Strict history-only feature construction and student-level train/validation/test splitting to avoid student and future-history leakage.
- Logistic Regression, Random Forest and XGBoost, evaluated with accuracy, precision, recall, F1, ROC-AUC and confusion matrices.
- Transparent weakness explanations, adaptive difficulty transitions, and unseen-question-aware recommendations.
- Streamlit Student, Simulation, and Analytics/Research modes.

## Reproducible experiment

`python run_demo.py` uses a fixed `SimulationConfig` and writes these generated artefacts:

- `data/generated/students.csv`, `questions.csv`, `attempts.csv`, `synthetic_truth.csv`, and `simulation_manifest.json`
- `data/processed/features.csv`, `predictions.csv`, and `recommendations.csv`
- `models/*.joblib` plus training metadata
- `experiments/results/model_comparison.csv`, confusion matrices and feature importance

For a model-only comparison run `python -m experiments.experiment_1`. Change student count, attempts, seed, learning rate, noise level and difficulty distribution in `SimulationConfig`. Results must always be regenerated after a configuration change; this repository intentionally does not hard-code metrics.

## Research design and limitations

**Question.** Can history, response time, difficulty and recent progression improve topic-mastery prediction and recommendation effectiveness versus non-adaptive selection?

**Protocols.** Compare random selection, a rule-based baseline and the proposed mastery-aware adaptive policy. Measure held-out mastery classification metrics, observed/simulated score improvement, time-to-threshold and question novelty/coverage. Keep all policies on identical seeded cohorts.

**Leakage controls.** Features at time *t* use only attempts before *t*. Students, not rows, are split between train/validation/test. The synthetic latent-mastery target is never a feature. A real deployment must replace it with independently collected, ethically approved assessment labels.

**Limitations.** The current question bank is a starter bank, synthetic learning behaviour is an assumption rather than empirical evidence, response time is simulated, and an ML model trained on synthetic labels is not validated for real learners. Any real student study needs consent, privacy review, protected storage, de-identification and a preregistered evaluation protocol.
